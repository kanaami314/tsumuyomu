# 論文棚(仮称)アイデアメモ

毎日論文を読む習慣を付けるための、読書記録アプリ(Web アプリ)のアイデアをまとめたメモ。
この段階では開発は始めず、方針とデザインの方向だけを決めている。

## 目的
- 論文を毎日読む習慣を付ける。
- そのモチベーションを維持するために、読んだ記録を付けられるようにする。
- 「論文は堅い」というイメージを和らげる。

## 参考にするサービス
- **読書メーター**: 一言感想で完結する軽さ、月ごとの累積。
- **ブクログ**: 本棚の見せ方、自作の棚、プロフィール。
- 両方の「いいとこどり」をする。論文には表紙がないので、表紙は自動で作る。

## 決まった方針

### 指標と習慣化
- **連続日数は廃止する**。途切れたときの落ち込みが大きいため。
- **累積を軸にする**。減らない数字だけを見せる。
  - 通算読了数、通算読了日数、今月、今年、月別の推移。
  - 次の節目(例: 「あと3本で90本」)を静かに示す。
- 空白の日を目立たせない。「◯日ぶり」のような経過日数は出さない。
- 目標(週や月の本数)は置かない、または緩く置く。

### 記録の入力
- 入力は軽くする。URL / DOI / arXiv ID を貼る → 書誌情報を自動取得 → 一言感想 → 保存。
- 詳細メモ、評価(刺さった度)、タグは任意。
- 読み方の深さ: じっくり / さらっと(アブストだけでも1本に数える)。
- ステータス: 読みたい / 読んでいる / 読了。

### 見せ方
- 「紹介できる書棚」を中心にする。
- **最初から公開前提**で作る(2026-10-22 に決定)。ただし、公開は強制せず、公開しなくても成立する設計にする。
- 公開の広がりは段階的に進める。
  1. アカウント、記録、書棚、公開・非公開の設定、公開 URL
  2. カード画像・サマリー画像の書き出し(共有用)
  3. ユーザー間の交流(フォロー、反応など)
- 論文の図表や PDF は転載しない。

### トーンとデザイン
- カジュアルでフランクだが、チープにしない。「論文」という語は残す。
- 利用者には、経験の浅い人や論文に不慣れな人も含める。
- 言葉づかいは、丁寧で温かい口調(です・ます)にする。「すごい!」の連発は避ける。
- 色は、生成りと若葉の緑を基調にして、自然な爽やかさを出す。
- 雰囲気は、おしゃれなカフェや図書館。

## デザインの方向(モックで確認済み)
`design/` フォルダに、見た目だけのモック(HTML)を置いている。
- `shelf4.html`: **採用した書棚**。背表紙を主体にして、ところどころ表表紙を向けた本を混ぜる。
- `immersive.html`: ホーム画面。写真に溶け込む案。上に店内写真、数字や入力欄はすりガラス。
- `index.html`, `shelf.html`, `shelf2.html`, `shelf3.html`: 途中の案(参考)。

### 書棚の決定事項
- 棚は、実物の1枚板のオーク材の写真から切り出したテクスチャを使う(継ぎ目や繰り返しを避ける)。
- 背表紙: 幅と高さを不揃いにし、縦書きのタイトルと出版年を入れる。布のような質感を重ねる。
- 表表紙: 紙の質感、ページの小口、背の綴じ目の陰影を付ける。
- **分野は、色としおり(リボン)で示す**。表紙に漢字のタグ名は載せない(野暮ったく見えたため)。
- 自作の棚(「じっくり読んだ」「人に勧めたい」など)を作れる。

### スマホ版の決定事項(`design/mobile.html`)
スマホ幅(375px)で、ホーム、書棚、記録の入力の3画面をモックにした。
- **ホーム**: 最近読んだ論文の**表紙カード1枚だけ**にする。
  - 店内写真を画面全体の背景にし、白い枠は付けず、表紙を写真の上に浮かべる(深い影)。
  - 累積は、見出しにさりげなく入れる(「87本目　10月20日」)。大きな数字や統計カードは置かない。
  - 下に、ひとことと刺さった度を置く。
  - 記録は、下のタブバーの中央ボタンに一本化する(ホームに入力欄は置かない)。
- **書棚**: 上に写真と小さなプロフィール、下に背表紙主体の棚。棚のチップは横スクロール。
- **記録の入力**: 下から出るシート。
  - 背景は、淡いグラデーション(右上に黄色の光、左下にミント、右に水色)。シートの上部に帯や装飾は置かない。
  - 手順は、DOI の貼り付け → 書誌情報の自動取得 → 読み方 → ひとこと → 刺さった度 → 棚 → 公開の切り替え。
  - 公開の切り替えは、既定をオフにする。
- **刺さった度は、ハートではなく「しおり」**で表す(表紙のリボンと揃える)。星、若葉、電球、付箋は不採用。
- タブバー: ホーム / 書棚 / 記録(中央の大きな丸ボタン) / ふりかえり / マイページ。

#### スマホ版の留意点(実装時)
- キーボードが出ると、シートの下半分が隠れる。シートをスクロールできる作りにする。
- 写真を全面に使うので、写真を切り替える場合は、どの写真でも文字が読めるようにする。
- 日本語の論文名は、縦書きの背表紙で長くなりやすい。省略のルールが要る。

### 素材の作り方
- 画像は生成 AI で作る(店内写真、木の板、背板など)。
- 「繰り返し用テクスチャ」より「1枚板の写真」を生成させたほうが、本物らしく見える。
- 公開や配布を考える段階で、使った生成サービスの利用規約を確認する。

## 決まったこと(2026-10-22)
- **分野は問わない(DOI 中心)**。DOI を貼って Crossref などから書誌情報を取得する。arXiv ID / URL も併用し、取得できない場合は手入力にする。
- **スマホ中心**。モバイルファーストで作る(片手での入力、貼り付けの手軽さ、ホーム画面に追加できる PWA など)。PC でも見られるようにする。
- **最初から公開前提**。アカウント、公開 URL、公開・非公開の切り替えを最初から作る。

### 決定による影響
- 技術構成は、ローカル完結(案 A)ではなく、**バックエンド + DB + 認証(案 B)** になる。
- MVP の範囲が広がる。記録と書棚に加えて、アカウント、公開プロフィール(書棚の公開 URL)、公開・非公開の設定が必要になる。
- 公開前提なので、プライバシーと権利の配慮が要る(論文の図表や PDF は転載しない、既定は非公開にするなど)。
- 既存のモックは PC 幅で作っているので、**スマホ幅のモック**(書棚、ホーム、記録の入力)を作り直す。縦長の写真素材(3:4 など)も必要になる。
- 共有用の見た目(OGP 画像、書棚のカード画像)を、早めに設計する。
