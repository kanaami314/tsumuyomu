# つむよむ 実装計画

`docs/idea-memo.md` の決定事項をもとに、作り方の計画をまとめる。
この文書は計画であり、コードはまだ書いていない。内容を確認してから、開発に入る。

## 1. 前提(決定済み)
- 論文を毎日読む習慣を付けるための、読書記録アプリ。スマホ中心、分野を問わない(DOI 中心)。
- 累積を軸にする(連続日数はない)。一言感想は任意。刺さった度は「しおり」。
- Google ログイン。**最初は招待制**(招待コード)。公開の既定は非公開。
- 基本は無料で運用する。Vercel は使わない。
- 見た目は `design/mobile.html` が本命(ホーム、書棚、記録シート)。

## 2. 技術構成

| 領域 | 採用 | 備考 |
|---|---|---|
| 画面 | React + Vite + TypeScript | 静的にビルドする SPA。スマホ向けの PWA にする |
| ホスティング | Cloudflare Workers(静的ファイルの配信) | GitHub の `main` への push で、自動公開。設定は `app/wrangler.jsonc`。Root directory は `app` |
| DB と認証 | Supabase(無料枠) | Postgres、Google ログイン、行ごとの権限(RLS) |
| 書誌情報の取得 | Crossref など(DOI) | 取得できないときは手入力。詳細は 5 章 |
| リポジトリ | GitHub `kanaami314/tsumuyomu` | 公開。秘密情報は、入れない |

- 画面は、サーバーを持たない静的な SPA にする。サーバー側の処理が要るもの(共有用の画像など)は、あとから Cloudflare Workers の処理を足す。
- 料金や無料枠の数字は、公開前に、公式の料金ページで確認する。

## 3. リポジトリの構成(案)
```
tsumuyomu/
├─ app/            画面(Vite + React + TypeScript)
├─ supabase/       DB の定義(migrations の SQL)と、RLS のテスト
├─ docs/           メモと計画
└─ design/         見た目のモックと素材(開発用のコードではない)
```
- `.env` は `.gitignore` に入れる。Supabase の `anon` キーは、画面に入れてよいが、`service_role` キーは、画面にも、リポジトリにも、置かない。

## 4. データの設計

### 表
| 表 | 主な列 | 役割 |
|---|---|---|
| `profiles` | id(= 認証のユーザー ID)、username(重複なし)、display_name、bio | 利用者の情報。公開 URL の名前 |
| `invite_codes` | code、created_by、max_uses、used_count、expires_at、disabled | 招待コード |
| `papers` | id、doi(重複なし)、arxiv_id、title、authors、year、venue、url | 論文の書誌情報(全員で共有) |
| `entries` | id、user_id、paper_id、status、read_on、depth、comment、rating、visibility | 1回の「読んだ」の記録。同じ論文を再読できる |
| `shelves` | id、user_id、name、visibility、position | 自作の棚 |
| `shelf_entries` | shelf_id、entry_id | 棚と記録の対応 |

- `status`: 読みたい / 読んでいる / 読了。`depth`: さらっと / じっくり。`visibility`: 非公開 / 公開(既定は非公開)。
- 累積(通算読了数、通算読了日数、月別)は、`entries` から、集計して出す。連続日数は、持たない。
- 分野の色としおりは、論文の分野(タグ)から決める。タグの持ち方(論文に付けるか、記録に付けるか)は、実装の中で決める。

### 権限(RLS)の方針
- すべての表で RLS を有効にする。
- `entries` と `shelves` は、**本人だけが、読み書きできる**。他の人には、`visibility = 公開` のものだけが、読める。
- `papers` は、誰でも読める(書誌情報だけ)。書き込みは、記録を作るときに限る。
- **プロフィールを持たないユーザー**(招待コードを使っていない人)は、どの表にも、書き込めない。
- 公開の棚の中に、非公開の記録がある場合は、**他の人には、公開の記録だけ**を見せる(実装前に確定する)。

## 5. 主な仕組み

### 招待とログイン
1. Google でログインする。
2. プロフィールが、まだなければ、**招待コードとユーザー名の入力画面**を出す。
3. コードを確かめる処理(DB の関数、`SECURITY DEFINER`)で、次を1回で行う。
   - コードが有効か(期限、回数、無効化)を確認する。
   - ユーザー名の重複を確認して、プロフィールを作る。
   - コードの使用回数を増やす。
4. プロフィールができて、はじめて、記録を作れる。
- Google でログインしただけの人は、認証の側には登録されるが、プロフィールがないので、何も書けない。実害は小さいが、この扱いでよいかを、実装のときに確認する。
- 招待コードの発行は、最初は、Supabase の管理画面から直接行う。

### 書誌情報の取得
- DOI を貼る → Crossref の API で、タイトル、著者、年、媒体を取得する。
- arXiv の ID や URL は、arXiv の DOI(`10.48550/arXiv.…`)に直して、取得する。
- **要確認**:
  - ブラウザから直接呼べるか(CORS)。呼べなければ、Cloudflare の Functions を挟む。
  - 日本の論文(JaLC の DOI)は、Crossref にない場合がある。取得できないときは、手入力の入力欄を出す。
- 取得できた書誌情報は、`papers` に保存して、再利用する。

### 公開と共有
- 公開のプロフィールは `/u/ユーザー名`。公開にした棚と記録だけを見せる。
- 画面が静的な SPA なので、ページごとの共有用の画像(OGP)は、最初の版では出せない。必要になったら、Functions で足す。

### PWA
- ホーム画面に追加できるようにする(マニフェストとアイコン)。オフラインで動かすことは、最初の版では、目標にしない。

## 6. 開発の段階(マイルストーン)

| 段階 | 内容 | 終わりの目安 |
|---|---|---|
| M0 準備(完了) | `app/` の雛形、型チェックと整形、GitHub Actions、Cloudflare の公開、Supabase のプロジェクト | `main` に push すると、公開先で、空の画面が見える |
| M1 見た目の移植(完了) | モックの見た目を、React の部品にする(書棚、ホーム、記録シート、タブバー)。データは、仮のもの | `design/mobile.html` と、ほぼ同じ見た目が、スマホで動く |
| M2 ログインと招待(完了) | Google ログイン、招待コード、ユーザー名、RLS | 招待コードのない人は、書き込めない。コードがある人は、登録できる |
| M3 記録の中核(完了) | DOI から取得、記録の作成・編集・削除、書棚に本物のデータを表示 | 記録して、書棚に背表紙が増える |
| M4 累積とふりかえり | 通算、今月、読んだ日、月別の推移、ふりかえりの画面 | 数字が、記録と一致する |
| M5 公開 | 公開・非公開の切り替え、`/u/ユーザー名`、公開の棚 | 招待した人に、公開の書棚を見せられる |
| M6 仕上げ | PWA、表示の調整、エラーの文言、招待コードの管理 | 招待した人に、安心して、渡せる |

- 各段階の終わりに、動作を確認して、コミットと push を行う。
- 大きな段階は、ブランチで作業して、`main` に取り込む運用にしてもよい。

## 7. テストと確認
- **RLS のテスト**を、最優先にする(他人の非公開の記録が、読めないことを確かめる)。
- 画面の部品は、Vitest などで、基本の動きを確認する。
- スマホ幅での見た目の確認は、実機とブラウザの両方で行う。
- 公開の前に、秘密情報(キー、トークン)が、リポジトリに入っていないかを確認する。

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| Supabase の無料プロジェクトが、1週間のアクセスなしで一時停止する | 利用者が少ない間は、定期的に使う。必要なら、定期アクセスを仕込む |
| 無料枠の上限(DB 500MB など)を超える | 招待制で、規模を小さく保つ。使用量を、ときどき確認する |
| 日本語の論文名が、縦書きの背表紙で長くなる | 省略のルールを決める(未決)。ホバーや詳細で全文を見せる |
| 書誌情報が取得できない | 手入力に、すぐ切り替えられる画面にする |
| 公開リポジトリに、秘密情報を入れてしまう | `.env` を除外する。コミット前に確認する |
| 生成画像の権利 | 公開や配布の前に、使った生成サービスの規約を確認する |
